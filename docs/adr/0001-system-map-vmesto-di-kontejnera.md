# ADR-0001: System map компонентов вместо DI-контейнера

- Статус: accepted
- Дата: 2026-08-25
- Связанные разделы SPEC: §2.2, §3.1, Часть II §1.3

## Контекст и постановка проблемы

Фреймворку уровня Laravel/Spring нужен механизм управления stateful-ресурсами (пулы соединений, серверы, планировщики): порядок старта/останова, зависимости, health, рестарт при hot reload. В JVM-мире это решается DI-контейнером с рефлексией и аннотациями; в Janet рефлексии нет, а философия проекта — «данные вместо аннотаций».

## Драйверы решения

- Инспектируемость из REPL — система должна быть видна как значение.
- REPL-driven development: рестарт отдельного компонента и его зависимых (reloaded workflow) без перезапуска процесса.
- Fail fast: ошибки графа (циклы, missing deps, дубли) должны ловиться до открытия портов.
- Отсутствие скрытых синглтонов и глобального состояния.

## Рассмотренные варианты

1. **System map в духе Integrant/Biff** — система = map компонентов; компонент — данные с функциями `start/stop/health/suspend/resume`.
2. **DI-контейнер с автосканом** (Spring-style) — авто-обнаружение компонентов, инъекция по типу/имени.
3. **Глобальные синглтоны + init-функции** (классический скриптовый стиль) — каждый модуль сам управляет своим состоянием.

## Решение

Вариант 1: **system map**. Registry компонентов → топологическая сортировка → старт в порядке зависимостей, стоп в обратном. `defcomponent` декларирует `:deps`, `:config` (schema своего куска), `:start/:stop/:health`, опционально `:suspend/:resume`.

Дополнительно:

- Валидация графа на старте: циклы, отсутствующие зависимости, дубли ключей — с указанием конфликтующих plugins.
- `(system/start)`, `(system/stop)`, `(system/restart :key)` — рестарт компонента и транзитивно зависимых.
- Scopes: `:singleton` (default) и `:factory` — для редких явных случаев.
- Интерфейсы через `:provides` (`:void/cache` и т.п.): зависеть можно от ключа или от интерфейса; две активных реализации без явного выбора в конфиге — ошибка старта.
- Единственное разрешённое «глобальное» состояние вне system map — `dyn` для request-scoped значений (per-fiber).

## Последствия

Плюсы:

- Система полностью инспектируема (`pp system`), компонент можно скопировать в проект и изменить (принцип копируемости из Biff).
- Порядок жизненного цикла детерминирован и проверяем в тестах (`plugin/dry-run`).
- `system/restart` даёт reloaded workflow без магии.

Минусы / цена:

- Явные декларации зависимостей — больше церемонии, чем автоскан.
- Компонентный контракт (`start/stop/health`) нужно поддерживать дисциплиной, а не типами.
- Interface-резолюция (`:provides`) добавляет ещё один слой непрямоты, который нужно объяснять в docs.
