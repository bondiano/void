# ADR-0037: `void/datastar` — страница как ответ, morph через SSE (эксперимент)

- Статус: accepted (experimental)
- Дата: 2026-08-31
- Связанные разделы SPEC: §5.5 (`void/htmx` — там записан сам эксперимент), §5.1 (SSE — часть контракта `void/http`), §5.4 (`void/html`)
- Связанные ADR: [0004](0004-data-first-dsl-kak-sahar.md) (данные прежде DSL), [0010](0010-concurrency-ev-loop-prefork-tls-vne-yadra.md) (границы процесса), [0016](0016-request-lifecycle-imenovannye-stadii.md) (фазовая шкала middleware), [0023](0023-auth-identity-i-strategii.md) / [0036](0036-i18n-slovar-kak-vklad-locale-kak-dyn-oshibki-perevodyatsya-sami.md) (identity и locale — dyn'ы, фибры их наследуют), [0028](0028-websocket-kak-marshrut-perehvat-soedineniya.md) (per-process реестр соединений, fan-out через шину), [0030](0030-forma-razvertyvaniya-i-razdelyaemye-hranilisha.md) (вопрос «я разделяемый?»)

## Контекст и постановка проблемы

SPEC §5.5 оставил закладку: «изучить Datastar-режим Biff (SSE + full-page morph) как альтернативную идиому — отдельный экспериментальный plugin». Идиома Biff переворачивает экономику гипермедиа: вместо того чтобы решать, *какой фрагмент* обновить (htmx: партиалы, OOB-свапы, retarget), handler на каждое действие рендерит **всю страницу**, а клиент морфит живой DOM до неё, сохраняя фокус, скролл и состояние инпутов. Плата за простоту — лишние байты рендера; выигрыш — исчезает целый класс решений «что именно изменилось», то есть исчезают и ошибки в этих решениях.

Datastar v1 читает два SSE-события: `datastar-patch-elements` (разметка, по умолчанию морфится по id верхнеуровневых элементов, либо по явному `selector` + `mode`) и `datastar-patch-signals` (JSON-патч сигналов страницы). Запросы он шлёт с заголовком `Datastar-Request: true`; сигналы едут query-параметром `datastar` на GET и JSON-телом иначе.

Вопросы, на которые пакет обязан ответить:

1. **Как из отрендеренной страницы сделать morph-события**, не нарушая документированный контракт Datastar (морф — по id или по селектору; поведение целого `<html>` как elements не документировано).
2. **Где это происходит.** Handler не должен знать о транспорте: та же функция обязана отвечать и браузеру полной страницей, и Datastar — событиями.
3. **Как страница живёт дальше.** Пуш-половина идиомы: соединение открыто, сервер ре-рендерит и толкает при каждом изменении. Кто держит соединения, кто будит, что при трёх репликах за балансировщиком (ADR-0030)?
4. **Сколько инфраструктуры заслуживает эксперимент.** Волна 5, вне критического пути; репозиторий уже умеет SSE (`ring/sse`, волна 0), рендер (`void/html`) и знает позу «реестр соединений per-process» (ADR-0028).

## Драйверы решения

- Всё уже построено: SSE-стриминг — это `ring/sse` поверх chunked-записи сервера («SSE rides on that», ADR-0015); рендер — `void/html`; различение клиента по заголовку и meta-ключ маршрута — поза `void/htmx` из волны 1. Пакет обязан быть композицией, а не вторым экземпляром чего-либо.
- Событие — данные (ADR-0004): билдеры wire-формата возвращают `{:event :data}`, который `ring/sse-event` кадрирует без переходника; они чистые и тестируются байт-в-байт.
- Re-render — по определению per-request-состояние: identity (ADR-0023) и locale (ADR-0036) живут в dyn'ах, и фибра стрима наследует их по построению — «своя страница» для каждого соединения не стоит ни одной передачи руками.
- Контракт Datastar задокументирован для морфа по id и по селектору; экспериментальный пакет не имеет права стоять на недокументированном поведении (целый `<html>` как elements).

## Рассмотренные варианты

**Как страница становится morph-событиями.** (1) Весь документ одним `elements` — отвергнуто: морф целого `<html>` не документирован (HTML-парсер внутри `<template>` выбрасывает `html`/`body`-теги), а эксперимент на недокументированном поведении — это два эксперимента. (2) Требовать от приложения id на каждом верхнеуровневом регионе body и слать регионы по отдельности — отвергнуто: это переписывание layout ради транспорта, и обновление `<title>` всё равно остаётся особым случаем. (3) **`<title>` по `selector title` + `<body>` по `selector body`** — принято: ровно два куска документа, недостижимые для id-матчинга, и оба документированы (обновление title через селектор — пример из документации Datastar). Срез — два `string/find` по готовым байтам; ни второго рендера, ни HTML-парсера. Разметка без `<body>` (fragment-handler) становится одним событием, морфящимся по id, — тот же meta-ключ обслуживает и фрагменты.

**Где стоит middleware.** (1) Глубже рендера (9500, как `:void.htmx/partial`) и рендерить самому — отвергнуто: понадобился бы доступ к контексту движка `void/html`, то есть второй рендер-пайплайн. (2) **Мельче рендера — фаза 8500** — принято: цепочка раскручивается изнутри наружу, к фазе 8500 view-ответ уже байты, и пакету достаётся готовая страница. Это зеркало htmx: тому нужен ответ **до** движка (снять layout), этому — **после** (переиспользовать рендер). Оба — `:when`-гейт по meta-ключу, немаркированный маршрут не платит ничего (§8.5).

**Как handler узнаёт клиента.** Расширение контракта ответа или отдельные маршруты — отвергнуто: `Datastar-Request: true` — тот же факт, что `HX-Request`, и поза уже есть — meta-ключ `:void.datastar/morph` + заголовок, один handler на оба представления.

**Live-половина.** (1) Только примитивы, fan-out — забота приложения — отвергнуто: идиома «страница живёт» не собирается из коробки, а пакет ради этой идиомы и существует. (2) Переиспользовать комнаты `void/ws` — отвергнуто: те держат сокеты и шлют кадры RFC 6455, здесь — каналы и ре-рендер; общее — только слово «room», а сходство имён — не причина для ребра между пакетами. (3) **Свой реестр: стрим паркуется на `ev/chan` ёмкостью 1, `poke!` будит комнату** — принято. Ёмкость 1 — это коалесценция по построению: второй poke до рендера пропускается, два poke — один рендер; так можно, **потому что** рендерится вся страница — состояние, а не дельта, и пропущенное пробуждение не теряет ничего. Каждое соединение ре-рендерит свой view само (dyn'ы identity и locale унаследованы фиброй), поэтому broadcast не рендерит «одну страницу на всех» — у всех она разная.

**Fleet.** Реестр — per-process, и это решение: соединение живёт в процессе, держащем сокет, реестр через процессы до него не дотянулся бы (дословно аргумент ADR-0028). Ответ на вопрос ADR-0030 — `:shared? :by-design` с named-`:why`; fan-out через реплики — подписчик `void/bus`, зовущий `poke!` локально.

**Сигналы и атрибуты.** Сигналы: GET — query `datastar`, иначе JSON-тело, keyword-ключи (как любое декодированное тело в void); malformed — 400 с текстом, не 500 из handler'а. Атрибуты — таблицы данных, поза `hx/attrs` буквально: `data-*`-имена из keyword'ов (двоеточие Datastar проходит насквозь: `:on:click` → `"data-on:click"`), словари JSON-кодируются, expression-билдер `action` собирает `@get('/live', {openWhenHidden: true})` с camelCase-опциями.

## Решение

### 1. `proto` — wire-формат как чистые функции

`patch-elements`, `patch-signals`, `remove-elements` возвращают `{:event :data}`; многострочная разметка — строка `elements` на строку, опции (`selector`, `mode`, `useViewTransition`, `onlyIfMissing`) — строки перед ней. `ring/sse-event` кадрирует значение как есть — `data:` на строку, как Datastar и читает.

### 2. Morph-middleware (фаза 8500) и meta-ключ

`:void.datastar/morph` (`:boolean`, `:merge :replace`). На Datastar-запрос отрендеренный `text/html`-ответ становится `text/event-stream`: событие `<title>` по селектору, событие `<body>` по селектору; статус и остальные заголовки (set-cookie в том числе) — как были. Обычный запрос проходит нетронутым: один handler, два представления, решение — per request.

### 3. `morph-stream` и `poke!`

`(datastar/morph-stream req view {:rooms [..]})` — SSE-ответ: фибра вступает в комнаты, по умолчанию толкает начальный morph (реконнект после обрыва ресинхронизирует устаревшую страницу) и паркуется на канале; `(datastar/poke! :room)` будит членов, каждый ре-рендерит `view` и толкает те же два события. Компонент `:datastar/registry` (`:deps [:http/server]` — drain закрывает стримы раньше листенера) закрывает каналы на stop; закрытый канал будит фибру значением nil — стрим завершается и выписывается из комнат.

### 4. Чего здесь нет

Нет `datastar.js` в пакете — скрипт подключается ассетом приложения, как htmx. Нет отдельного execute-script-события — v1 его убрал, скрипт — это `patch-elements` с `<script>`-элементом, когда понадобится. Нет авто-`Vary` и кэш-политики — morph-ответ не кэшируется по построению (`cache-control: no-cache` на SSE). Нет durable-доставки: пропущенное при обрыве соединения не переигрывается — следующий морф несёт всё состояние, в этом идиома. Нет второй шины: fan-out через реплики — подписчик `void/bus` + локальный `poke!`, точек и контрактов для этого не нужно.

## Последствия

**Хорошо.** Handler пишется один раз и не знает о транспорте — та же функция отдаёт документ браузеру, morph Datastar'у и, обёрнутая в `morph-stream`, живую страницу; «что именно изменилось» перестаёт быть вопросом кода приложения. Пакет — тонкая композиция построенного: SSE волны 0, рендер волны 1, поза meta-ключа волны 1, поза реестра ADR-0028; ни одного нового native-модуля, ни одной новой точки расширения. Wire-формат тестируется байт-в-байт без boot'а, идиома целиком — inject'ом без сокета (ADR-0017).

**Цена.** Каждое действие рендерит и везёт всю страницу — это осознанный размен байтов на простоту; приложению, где это дорого, htmx-идиома никуда не делась, и обе живут на одном `void/html`. Срез `<body>` — поиск по байтам, а не парсер: страница, кладущая литерал `"<body"` в inline-скрипт до настоящего body, получит неверный срез (названо здесь, чтобы не чиниться молча). `<head>` за пределами `<title>` морфом не обновляется — и не должен: ассеты меняются деплоем, а не запросом. `poke!` будит только свой процесс — три реплики требуют bus-подписчика, и проверка ADR-0030 не скажет об этом ни слова, потому что реестр честно `:by-design`.
