# ADR-0007: Config — слои с provenance, schema-валидация до старта, secrets-ссылки

- Статус: accepted
- Дата: 2026-08-25
- Связанные разделы SPEC: §2.6, §3.2, Часть II §1.2 (фаза config)

## Контекст и постановка проблемы

Конфигурация приходит из многих источников (defaults плагинов, файлы, env vars, CLI), различается по профилям (dev/test/prod) и содержит секреты. Классические боли: «откуда взялось это значение?», ошибка конфигурации всплывает первым запросом в проде, секрет утёк в лог.

## Драйверы решения

- Fail fast (принцип §2.6): ошибка конфигурации не должна доживать до первого запроса.
- Отлаживаемость: происхождение каждого значения должно быть запрашиваемо.
- Ошибки — пачкой по всем plugins, не first-fail (один прогон CI — полный список проблем).
- Секреты не печатаются никогда, включая REPL.

## Рассмотренные варианты

1. **Слоёный merge с отслеживанием происхождения** + per-plugin schema-валидация на фазе bootstrap.
2. **Плоский env-only** (12-factor минимализм) — просто, но нет структуры, валидации пачкой и defaults плагинов.
3. **Код-как-конфиг без слоёв** (единый config.janet) — гибко, но профили и env-overrides превращаются в ручные if-ы.

## Решение

Вариант 1. Слои в порядке приоритета: defaults плагинов ← файлы `config/*.janet|jdn` ← env vars (`VOID_DB__HOST=...`) ← CLI overrides. Merge отслеживает происхождение каждого значения: `(config/explain :database :host)` → «env var VOID_DB__HOST».

- Профили `:dev`/`:test`/`:prod` + произвольные.
- Каждый компонент/plugin декларирует schema своего `:config-key`; вся конфигурация валидируется на фазе 2 bootstrap, до какого-либо старта; ошибки собираются пачкой.
- Secrets: значения-ссылки `{:secret "DB_PASSWORD"}` резолвятся из env/file/vault-plugin (источники — extension point `:void.core/config-source`); custom print гарантирует, что значение не печатается в логах/REPL.
- Conditional activation plugins (`:when`) считается по уже провалидированному конфигу.

## Последствия

Плюсы:

- `config/explain` закрывает главный класс вопросов эксплуатации.
- Невалидный конфиг физически не может дойти до открытия портов; `plugin/dry-run` даёт ту же проверку в CI.
- Vault/consul добавляются plugin'ом без изменения ядра.

Минусы / цена:

- Merge с provenance дороже наивного merge — но исполняется один раз на старте (бюджет startup < 150 ms учитывает это).
- Схема на каждый кусок конфига — обязательная церемония для авторов plugins.
- Двойное подчёркивание в env-нейминге (`VOID_DB__HOST`) — конвенция, которую нужно один раз выучить.
